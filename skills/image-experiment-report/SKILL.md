# 图像实验报告

## 写作要求

读者是有技术背景的同事。可以使用术语，不默认解释基础概念。

先写本次验证的问题、结论和关键证据，再给方法与参数。直接围绕实验问题写，不扩成教程；删除重复总结、空泛背景和没有信息增量的句子。篇幅由证据决定，不为凑章节重复内容。

## 工作步骤

1. 读取已有实验材料，确定输入、处理方法、输出及对应关系。只整理用户指定的实验；未经要求不重新生图、不调用付费服务、不改项目。
2. 将原始输入输出原样复制到独立报告文件夹。保留已有工作流、关键参数、必要脚本和运行记录；缺失项写“未记录”，不猜测。检查材料中的密码、密钥等凭据，不能打包泄露。
3. 实际查看图片再写视觉结论。正文展示输入和结果；需要局部对照时使用相同位置、倍率和显示条件，注明裁切坐标及缩放。标注、拼图和差异增强图单独保存，不覆盖原图，不把增强差异当作肉眼可见程度。
4. 编写报告。每张展示图附近链接对应原始文件。事实、视觉观察、测量和原因推断分清；没有观察到差异就如实写。“未复现”不等于“排除原因”，单次结果不推广成普遍规律。
5. 检查图片、链接、文件对应关系和结论边界，再把整个报告文件夹打成 ZIP。所有操作限于本次材料和输出目录，保留已有实验记录。

## 建议正文

- 问题与结论：本次要验证什么，结果支持什么。
- 图像证据：原图与结果对照，必要的局部细节。
- 方法与参数：输入来源、模型与版本、主要参数；对照中改变和保持的条件。注明裁切、缩放、补边、融合、调色等实际步骤。
- 限制：哪些原因还无法判断，缺哪些复现材料。必要时只提一个下一步实验。

按实验合并或调整章节，不需要填写空洞的固定栏目。

## 文件与交付

默认结构：

```text
日期-实验名称/
├─ 报告.md
├─ 原图/          输入与输出原始文件
├─ 对比图/        阅读用整图对照、局部放大等
└─ 复现材料/      已有工作流、参数、脚本、必要记录
```

实验统一默认保存在 `F:\Longpean-AIGC\25-实验`，每次建立 `日期-实验名称` 子文件夹，报告、原始图片、对比图和复现材料放在一起，ZIP 放在该子文件夹旁。用户当次明确指定其他位置时以当次要求为准。不覆盖同名历史报告，不自动迁移已有实验。

- 原图保留原始文件字节、尺寸和格式，不通过重新编码或缩小节省体积；复制后可用哈希核对。输入若只有截图，注明是用户提供的截图/粘贴图，未取得更上游源文件。
- 远程图片在允许下载时保存本地副本并记录来源，不能仅保留可能失效的网址；无法取得源文件时明确缺失，不以预览冒充原图。
- 报告内使用相对链接，确保搬走整个文件夹仍可打开；对用户交付的文件链接使用绝对路径。
- 复现材料说明依赖、模型版本已知程度和运行入口；不能因保存了种子就声称完全可复现。若原脚本依赖外部路径，补齐依赖或说明，不伪称独立可运行。
- 默认交付 Markdown、完整文件夹和 ZIP；PDF/HTML 按需另做，只作为阅读版，不能替代原图存档。
- 验证 ZIP 内含报告所引用的全部材料。最终回复简短，给报告与完整包入口，不再重复整份报告。
